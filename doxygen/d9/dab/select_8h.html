Detailed Description

Picks the way to run a request that meets the caller's limits and costs least.

A request can be run several ways: the decode scale, the filter and the decode effort (the lattice of tiny_plan_enumerate), then the output format and its quality. The budget ladder walks one path through the first three and takes the output format as given. The selector searches all of it.

What it knows, and from where:

  • time: the calibrated upper bound of tiny_plan_cost_upper for the lattice point plus tiny_encode_cost_upper_for for the output, times the caller's machine factor;
  • memory: tiny_plan_peak_bytes through the lattice;
  • quality: tiny_distortion_lever and tiny_distortion_encode, composed by adding noise power, as a predicted PSNR against the plan's own undegraded output;
  • bytes: the median bytes per output pixel of tiny_distortion_encode.

What it does not know: how many bytes this image will encode to, and how much error this image will show. Both are table medians and percentiles over other images. See tiny_select_compose_db and TinySelection.

◆ TinySelectReason

enum TinySelectReason

The constraint that removed a candidate, in the order they are checked.

A candidate is removed by the first check it fails, so a candidate removed by TINYIMG_SELECT_REASON_PEAK was never tested against the later ones. The time bound is computed only for candidates that passed every check before the budget. The numbers order the checks, which is what a whole-search reason is read from: the largest value among the candidates, the constraint the nearest miss failed.

◆ tiny_plan_select()

int tiny_plan_select ( const TinyPlan * plan,
const TinySelectOpts * opts,
TinySelection * selection )

Searches every way to run the plan and picks the best that fits.

Tries each point of tiny_plan_enumerate's lattice (at most 16) at each output format and quality tier (at most 18 variants), 288 candidates at most, removing a candidate by the first check it fails, in the order of TinySelectReason: the format mask, alpha, an UNCHARACTERIZED class, the peak heap cap, the quality floor and then the time budget. The time bound is priced only for candidates that reach the budget check. Among those that meet every limit it takes the best by objective, a tie goes to the secondary key the objective names, and a tie in both goes to the earlier candidate in search order (lattice point, then variant), so the answer is a pure function of the plan and the options.

Cost: the lattice enumeration, one extra resolution of the plan and 18 encoder prices, then table lookups per candidate. No pixel is read and no clock is. The plan's own budget, basis and degraded state are ignored; the limits are the options'.

Each point's time bound is its TinyPlanCandidate::cost_upper, the same figure tiny_plan_cost_upper gives for the plan resolved at that point. The encoder's upper bound is added and the sum is scaled by scale_milli, rounded up.

A prediction under exchangeability, not a guarantee. See TinySelection for what each predicted figure is and its measured coverage.

Parameters
planThe plan, which may carry a budget.
optsThe limits and objective, or NULL for the defaults.
selectionReceives the decision.
Returns
int TINYIMG_OK, TINYIMG_ERR_NULL, TINYIMG_ERR_RANGE for an unknown objective or uncharacterized mode, or what tiny_plan_enumerate returns. An infeasible search is TINYIMG_OK with feasible zero.

The independent policy: format and quality by bytes, then the ladder.

Picks the output format and tier with the fewest predicted bytes per pixel that pass the alpha, mask, UNCHARACTERIZED and quality checks at the undegraded decode, ignoring CPU and memory, whatever objective says. Then runs the ladder as tiny_plan_select_ladder does, with the budget left after that encoder, and evaluates the rung it settles on against every limit. This is the way a caller who chooses the format first and the degradation second would behave.

◆ tiny_plan_select_ladder()

int tiny_plan_select_ladder ( const TinyPlan * plan,
const TinySelectOpts * opts,
TinySelection * selection )

The fixed policy: today's budget ladder, then the encoder as given.

Takes the output format to be the source's own when formats allows it, else the lowest format in the mask, at that format's default quality. The encoder is priced first, the ladder of tiny_plan_resolve runs on the upper bound with the budget left after it, as tiny_plan_admit does in TINYIMG_ADMIT_DEGRADE mode, and the rung it settles on is the one candidate evaluated. The limits are checked on it as on any candidate, so a ladder choice that breaks the peak cap or the floor is reported infeasible rather than adjusted. objective is not read.

Because the format and tier are in the joint search's space and the rung is in its lattice, the joint search is never worse than this on the objective when this is feasible.

◆ tiny_select_compose_db()

float tiny_select_compose_db ( TinyDistortionClass lever_class,
float lever_db,
TinyDistortionClass encode_class,
float encode_db )

Composes a lever's quality and an encoder's by adding noise power.

db = -10 log10(10^(-lever_db / 10) + 10^(-encode_db / 10)), with an EXACT part contributing no noise and the result capped at 99 dB, the figure the tables use for identical outputs.

The assumption is that the two errors are independent, so their noise powers add. The encoder's figure was measured on the undegraded pixels, not on the lever's output, and both figures are percentiles of distributions over images, so the composition is a model of the quality and not a measurement of it. Adding a part never raises the result: the composed value is at most the lower of the two.
